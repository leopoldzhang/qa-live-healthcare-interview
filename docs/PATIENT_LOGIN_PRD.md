# 患者登录注册功能 PRD

## 1. 需求背景
当前系统使用姓名+生日验证患者身份,存在以下问题:
1. 用户体验不佳: 每次都需要输入姓名和生日验证
2. 安全性不足: 仅凭姓名和生日无法有效验证身份
3. 无法提供账户管理功能: 用户无法修改密码、找回账户等

因此需要实现患者注册和登录功能,使用用户名+密码的方式进行身份验证。

## 2. 功能描述
### 2.1 用户注册
- 用户填写注册表单: 用户名、密码、确认密码、姓名、生日、手机号、性别
- 系统验证用户名唯一性
- 系统验证密码强度
- 注册成功后自动登录

### 2.2 用户登录
- 用户输入用户名和密码
- 系统验证用户名和密码
- 登录成功后跳转到问诊页面

### 2.3 用户登出
- 清除当前登录状态
- 返回登录页面

## 3. 用户故事
- 作为问诊患者,我希望使用用户名和密码登录,以便更安全地管理我的账户
- 作为问诊患者,我希望可以注册账户,以便使用系统的各项功能
- 作为问诊患者,我希望可以修改密码,以便保证账户安全

## 4. 功能流程

### 4.1 注册流程
```
用户访问注册页面
  ↓
填写注册信息(用户名、密码、确认密码、姓名、生日、手机号、性别)
  ↓
前端表单验证(必填项、密码强度、密码一致性)
  ↓
提交注册请求
  ↓
后端验证用户名是否已存在
  ↓
密码加密存储(BCrypt)
  ↓
创建患者记录
  ↓
返回注册成功
  ↓
自动登录并跳转到问诊页面
```

### 4.2 登录流程
```
用户访问登录页面
  ↓
输入用户名和密码
  ↓
前端表单验证
  ↓
提交登录请求
  ↓
后端验证用户名和密码
  ↓
返回用户信息
  ↓
存储登录状态(localStorage)
  ↓
跳转到问诊页面
```

### 4.3 业务规则
- 用户名: 4-20位字母、数字、下划线,不能以数字开头
- 密码: 6-20位,必须包含字母和数字
- 生日格式: YYYY-MM-DD
- 手机号格式: 11位数字
- 性别: 男/女
- 同一用户名只能注册一次
- 密码使用 BCrypt 加密存储

## 5. 技术方案

### 5.1 技术架构
- 前端: Vue 3 + Composition API + Ant Design Vue
- 后端: Spring Boot + JPA + H2/MySQL
- 密码加密: BCrypt
- 状态持久化: localStorage

### 5.2 接口设计

| 接口名称 | 请求方式 | 路径 | 参数 | 返回值 |
|---------|---------|------|------|--------|
| 患者注册 | POST | /api/auth/patient/register | { username, password, name, birthday, phone, gender } | { code, data, message } |
| 患者登录 | POST | /api/auth/patient/login | { username, password } | { code, data: { id, username, name, birthday, phone, gender, createdAt }, message } |
| 患者登出 | POST | /api/auth/patient/logout | {} | { code, message } |
| 检查用户名 | GET | /api/auth/patient/check-username?username=xxx | username | { code, data: { exists: boolean }, message } |

### 5.3 数据模型

#### 表名: patients
| 字段名 | 类型 | 是否必填 | 说明 | 索引 |
|-------|------|---------|------|------|
| id | VARCHAR(50) | 是 | 主键,自动生成 | PRIMARY KEY |
| username | VARCHAR(50) | 是 | 用户名,唯一 | UNIQUE INDEX |
| password | VARCHAR(100) | 是 | 密码(BCrypt加密) | - |
| name | VARCHAR(50) | 是 | 姓名 | - |
| birthday | DATE | 是 | 生日 | - |
| phone | VARCHAR(20) | 否 | 手机号 | - |
| gender | VARCHAR(10) | 否 | 性别(男/女) | - |
| created_at | TIMESTAMP | 是 | 创建时间 | - |
| updated_at | TIMESTAMP | 是 | 更新时间 | - |

## 6. 前端交互

### 6.1 页面列表
- 登录页面: `/patient/login` - 用户名密码登录表单
- 注册页面: `/patient/register` - 完整注册表单
- 首页: `/` - 添加登录/注册入口
- 问诊页面: `/consultation` - 已登录显示问诊界面,未登录跳转到登录页

### 6.2 表单验证
#### 登录表单
- 用户名: 必填,长度4-20位
- 密码: 必填,长度6-20位

#### 注册表单
- 用户名: 必填,4-20位字母数字下划线,不以数字开头,需要实时验证唯一性
- 密码: 必填,6-20位,必须包含字母和数字
- 确认密码: 必填,必须与密码一致
- 姓名: 必填,2-20位中文
- 生日: 必填,日期格式
- 手机号: 选填,11位数字
- 性别: 选填,男/女

### 6.3 UI设计
- 登录页面: 居中卡片式布局,简洁美观
- 注册页面: 居中卡片式布局,分步骤表单
- 密码输入框: 支持显示/隐藏切换
- 表单提示: 实时验证,显示错误提示

## 7. 异常处理

### 7.1 错误码定义
| 错误码 | 说明 | 处理方式 |
|-------|------|---------|
| 1001 | 用户名已存在 | 提示用户更换用户名 |
| 1002 | 用户名或密码错误 | 提示用户检查输入 |
| 1003 | 用户不存在 | 提示用户先注册 |
| 1004 | 参数验证失败 | 提示具体错误信息 |
| 1005 | 系统错误 | 提示"系统繁忙,请稍后重试" |

### 7.2 异常场景
- 用户名已存在注册: 提示"该用户名已被注册,请更换"
- 用户名密码错误登录: 提示"用户名或密码错误"
- 网络错误: 显示网络错误提示,提供重试按钮
- 未登录访问问诊页: 自动跳转到登录页,登录成功后返回

## 9. 风险与限制

### 9.1 风险点
| 风险 | 描述 | 影响 | 缓解措施 |
|------|------|------|---------|
| 密码安全 | 密码存储安全 | 数据泄露导致账户被盗 | 使用 BCrypt 加密,设置合理的 cost factor |
| 并发注册 | 多个用户同时注册相同用户名 | 重复数据 | 数据库唯一索引约束,事务处理 |
| XSS 攻击 | 恶意脚本注入 | 用户信息泄露 | 前端输入过滤,后端参数验证 |
| CSRF 攻击 | 跨站请求伪造 | 未授权操作 | 添加 CSRF token,验证 Referer |

### 9.2 限制条件
- H2 数据库用于开发环境,生产环境需要 MySQL
- 登录状态存储在 localStorage,不支持无痕浏览
- 当前版本不支持记住密码功能
- 当前版本不支持第三方登录
